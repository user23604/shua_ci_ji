## 2. 必须先理解的事故背景

本项目曾发生 P0 数据事故：

1. 用户在 2026-06-18 使用网页刷词约 1 小时。
2. 页面右上角同步灯最终显示绿色或无异常。
3. GitHub Gist 没有 2026-06-18 对应 revision。
4. 用户后续清理浏览器缓存/网站数据后，本地数据消失。
5. rescue 工具检查手机和平板 localStorage 后，没有发现 2026-06-18 学习数据。
6. 事故中发现本地配置曾出现 `token === gistId`，说明 PAT 与 Gist ID 填写或保存出现严重问题。

本次整改的核心目标：

> 禁止“假同步成功”。宁可显示红色失败，也不能让用户误以为云端已保存。

## 3. 当前代码中的关键风险点

### 3.1 状态灯语义错误

当前代码中 `setSyncStatus(status)` 会把 `ok` 和 `error` 都在短时间后隐藏/回到 `idle`。这是数据安全系统中的严重问题。

风险：

- 用户错过错误提示；
- 红色失败消失后看起来像正常；
- 绿色可能只是“无变化”或“拉取成功”，不是“云端保存成功”。

必须改。

### 3.2 `setSyncStatus("ok")` 被过度使用

当前代码在多种场景调用 `setSyncStatus("ok")`，包括：

- 云端没变、本地没变；
- 自动 Pull 云端成功；
- 自愈修复本地；
- PATCH 成功。

这些场景不能都显示同一种绿色。特别是：

- Pull 成功不等于本地新数据已上传；
- 没有变化不等于云端保存成功；
- read-only fallback 更不能显示成功上传。

### 3.3 GitHub PAT 与 Gist ID 没有硬校验

当前 `normalizeCloudConfig()` 只判断 token 和 gistId 是否非空：

```js
return Boolean(state.cloud.token && state.cloud.gistId);
```

这远远不够。必须阻止：

- token 为空；
- gistId 为空；
- token === gistId；
- token 看起来像 Gist ID；
- gistId 看起来像 PAT；
- PAT 无法 GET Gist；
- PAT 无法 PATCH Gist。

### 3.4 云同步字段 UI 都是 password，容易误填

当前 GitHub PAT 和 Gist ID 都以 password input 显示。用户无法肉眼确认 Gist ID 是否填错。

建议：

- PAT 使用 password，但加“显示/隐藏”按钮；
- Gist ID 使用普通 text 或默认显示后 6 位；
- 显示字段校验结果；
- 如果 token 与 gistId 相同，立即红色报错并禁止保存。

### 3.5 配置输入时自动触发 Pull 风险过高

当前代码在 token/gist 输入框 `input` 事件中直接：

```js
persistCloud();
queueAutoPull("config");
```

风险：

- 用户还没输入完 token，就触发 API 请求；
- 半截 token 导致 401；
- 错误状态混乱；
- 可能触发 read-only fallback 或其他同步流程。

必须改成：

- 用户点击“保存并测试连接”按钮后才连接 GitHub；
- 输入时只更新临时 draft，不写正式 cloud config；
- 测试通过后才保存到 `vocab_machine_cloud_v1`。

### 3.6 pagehide / visibilitychange 上传不可靠

当前代码在页面隐藏或关闭时：

```js
autoPushToGist({ keepalive: true })
```

移动浏览器中该请求不可靠。它可以保留为辅助，但不能作为主同步。

必须建立：

- 学习中周期性主动同步；
- 操作后 debounce 同步；
- 失败时持久提示；
- 本地 pendingOps 不丢。

### 3.7 没有本地每日备份

当前系统依赖 localStorage 主业务 key 和 pendingOps。一旦 localStorage 被清理，没有第二本地副本。

必须新增：

- `vocab_machine_local_snapshot_latest_v1`
- `vocab_machine_daily_backup_YYYY-MM-DD`
- `vocab_machine_sync_audit_v1`

### 3.8 read-only fallback 语义需要调整

当前代码支持 PAT 无效时不带 token 读取公开 Gist。这个可以保留，但必须明确显示：

> 当前只是只读恢复，不能上传。

禁止在 read-only 模式下显示绿色“同步成功”。

### 3.9 Service Worker 需要简化和可控

当前包中 `sw.js` 为极简清缓存版本。生产版必须明确策略：

- P0 修复阶段可以先禁用复杂缓存；
- 不要缓存 `app.js` 导致旧逻辑长期运行；
- `rescue.html` 不应被 Service Worker 干扰；
- 所有部署版本应带 `APP_VERSION` 并在 UI 显示。

## 4. 新的同步状态模型

请废弃当前模糊的四态：

```txt
idle / syncing / ok / error
```

改为数据语义明确的状态：

```js
const SYNC_STATES = {
  UNCONFIGURED: "unconfigured",
  INVALID_CONFIG: "invalid_config",
  LOCAL_ONLY: "local_only",
  DIRTY: "dirty",
  SYNCING: "syncing",
  CLOUD_SAVED: "cloud_saved",
  READ_ONLY: "read_only",
  ERROR: "error",
  CONFLICT: "conflict"
};
```

### 状态含义

| 状态 | UI 颜色 | 含义 |
|---|---|---|
| `UNCONFIGURED` | 灰色 | 未配置云同步 |
| `INVALID_CONFIG` | 红色 | PAT/Gist 配置错误 |
| `LOCAL_ONLY` | 橙色 | 本地已保存，但云端未配置或不可写 |
| `DIRTY` | 橙色 | 有本地 pendingOps 未上传 |
| `SYNCING` | 蓝色/黄色 | 正在同步 |
| `CLOUD_SAVED` | 绿色 | 最近本地改动已成功 PATCH 到 Gist |
| `READ_ONLY` | 橙色 | 只能读 Gist，不能写 |
| `ERROR` | 红色 | 最近一次同步失败，云端未保存 |
| `CONFLICT` | 红色 | 存在无法自动处理的冲突 |

### 绿色的唯一条件

只有以下函数成功后，才能设置绿色：

```js
patchGistFiles() -> response.ok === true -> response.json() -> 得到新 remoteVersion -> markSyncedWithRemote() -> clearPendingOps()
```

其他任何路径都不能显示绿色。

## 6. GitHub 配置校验要求

### 6.1 格式校验

新增函数：

```js
function validateCloudConfigDraft({ token, gistId }) {
  const errors = [];

  if (!token) errors.push("GitHub PAT 不能为空");
  if (!gistId) errors.push("Gist ID 不能为空");
  if (token && gistId && token === gistId) errors.push("GitHub PAT 和 Gist ID 不能相同");

  if (/^[a-f0-9]{20,64}$/i.test(token)) {
    errors.push("GitHub PAT 看起来像 Gist ID，请检查是否粘贴错位置");
  }

  if (/^(ghp_|github_pat_|gho_|ghu_|ghs_|ghr_)/.test(gistId)) {
    errors.push("Gist ID 看起来像 GitHub Token，请检查是否粘贴错位置");
  }

  return { ok: errors.length === 0, errors };
}
```

### 6.2 测试连接按钮

不要在 input 事件中自动 Pull。改为：

1. 用户输入 token 和 gistId；
2. 点击“测试并保存云同步配置”；
3. 前端执行：
   - 格式校验；
   - GET Gist；
   - PATCH `sync.healthcheck.json` 或执行安全写入测试；
4. 成功后才保存到 `vocab_machine_cloud_v1`；
5. 失败时不保存，红色常驻。

### 6.3 写权限测试

仅 GET 成功不够。必须测试写权限。

建议 PATCH：

```js
files: {
  "sync.healthcheck.json": {
    content: JSON.stringify({ at: new Date().toISOString(), clientId }, null, 2)
  }
}
```

写权限测试成功后，才认为云端可写。

## 7. 同步流程重构要求

### 7.1 本地操作时

每个学习操作必须做三件事：

```txt
1. 写业务 localStorage
2. 写 pendingOps
3. 写 local snapshot / daily backup
```

不能只写业务 key。

### 7.2 pendingOps 规则

- Push 成功前绝不清空。
- 失败绝不清空。
- Pull 云端绝不清空本地未上传操作，除非本地没有 dirty 数据。
- pendingOps 数量 > 0 时 UI 必须橙色。

### 7.3 主动同步

新增：

```js
const AUTO_PUSH_INTERVAL_MS = 15000;
const AUTO_PUSH_DEBOUNCE_MS = 3000;
```

策略：

- 学习操作后 debounce 3 秒同步；
- 学习中每 15 秒如果有 pendingOps 则同步；
- 离开页面时只做最后一次尝试，不依赖它。

### 7.4 Push 成功判定

只有以下条件都满足，才算 Push 成功：

```js
response.ok === true
&& updatedGist.history?.[0]?.version
&& markSyncedWithRemote() 完成
&& clearPendingOps() 完成
```

### 7.5 Push 失败处理

Push 失败必须：

1. 保留 pendingOps；
2. 保留 local snapshot；
3. 写 audit log；
4. UI 红色常驻；
5. 设置页显示具体错误；
6. 禁止显示绿色。

## 9. 当前代码具体修改位置

### 9.1 `setSyncStatus()`

当前问题：`ok` 和 `error` 都会短时间后回 idle。

要求：

- 改成持久状态；
- 只有临时 `syncing` 可以自动变化；
- error、dirty、local_only、read_only 必须常驻；
- 状态要基于 pendingOps 和 lastSuccessfulPushAt 计算，而不是随便手动设置。

### 9.2 `renderSyncIndicator()`

当前只显示一个点。

要求：

- 增加 tooltip / aria-label / 可见文字；
- 点击后展开同步详情；
- 不同状态颜色明确。

### 9.3 `normalizeCloudConfig()`

当前只判断非空。

要求：

- 改名为 `validateSavedCloudConfig()`；
- 不能自动保存错误输入；
- 检查 token 与 gistId 是否相同；
- 检查形态是否互相粘反。

### 9.4 `bindSetupEvents()` 中 token/gist input

当前 input 事件直接保存并同步。

要求：

- 改为临时 draft；
- 新增按钮“测试并保存”；
- 测试成功后才 persistCloud；
- 输入变化时不触发 queueAutoPull。

### 9.5 `patchGistFiles()`

要求：

- Push 前写 audit event：`push:start`；
- response 非 ok 写 `push:failed`；
- response ok 后写 `push:succeeded`；
- 成功后更新 `lastSuccessfulPushAt`；
- 成功后状态设为 `CLOUD_SAVED`；
- 失败时状态设为 `ERROR`，不清 pendingOps。

### 9.6 `runGistSync()`

要求：

- 不要在 `!remoteChanged && !localChanged` 时直接绿色；
- 如果从未成功 Push，只能显示“云端无新变化”或灰色；
- read-only fallback 只能显示橙色只读；
- Pull 成功不等于 Push 成功。

### 9.7 `recordStudyActivity()` / `saveProgress()` / `saveUnknownProgress()` / `markWord()` / `undoMark()` / `recordUnitCompletion()`

要求：每次学习数据变化后必须调用：

```js
markLocalDirty();
appendPendingOp(...);
writeLocalSnapshot();
writeDailyBackup();
scheduleAutoPush();
```

### 9.8 `sw.js`

P0 修复期间建议：

- 不缓存 `app.js`；
- 或每次版本变更强制清旧 cache；
- `rescue.html` 不应被拦截；
- UI 显示当前 app version。

## 10. 新增函数建议

### 10.1 `markLocalDirty()`

```js
function markLocalDirty() {
  const now = new Date().toISOString();
  state.syncMeta.localUpdatedAt = now;
  if (!state.syncMeta.dirtySince) state.syncMeta.dirtySince = now;
  persistSyncMeta();
  updateSyncStateFromFacts();
}
```

### 10.2 `updateSyncStateFromFacts()`

```js
function updateSyncStateFromFacts() {
  const opsCount = getPendingOps().length;
  const cloud = validateSavedCloudConfig(state.cloud);

  if (!cloud.ok) return setPersistentSyncState("invalid_config", cloud.errors.join("；"));
  if (opsCount > 0) return setPersistentSyncState("dirty", `本地有 ${opsCount} 条记录待上传`);
  if (state.syncMeta.lastSuccessfulPushAt) return setPersistentSyncState("cloud_saved", `云端已保存：${state.syncMeta.lastSuccessfulPushAt}`);
  return setPersistentSyncState("local_only", "本地已保存，尚未确认云端保存");
}
```

### 10.3 `writeLocalSnapshot()`

```js
function writeLocalSnapshot(reason = "change") {
  const payload = normalizeSyncPayload(collectSyncPayload());
  localStorage.setItem("vocab_machine_local_snapshot_latest_v1", JSON.stringify({
    reason,
    savedAt: new Date().toISOString(),
    payload
  }));
}
```

### 10.4 `writeDailyBackup()`

```js
function writeDailyBackup(reason = "change") {
  const date = localDateKey();
  const payload = normalizeSyncPayload(collectSyncPayload());
  localStorage.setItem(`vocab_machine_daily_backup_${date}`, JSON.stringify({
    reason,
    savedAt: new Date().toISOString(),
    payload
  }));
}
```

### 10.5 `appendAuditEvent()`

```js
function appendAuditEvent(event) {
  const store = loadJson("vocab_machine_sync_audit_v1", { events: [] });
  const events = Array.isArray(store.events) ? store.events : [];
  events.push({
    id: createOpId(),
    at: new Date().toISOString(),
    pendingOpsCount: getPendingOps().length,
    localUpdatedAt: state.syncMeta.localUpdatedAt,
    lastRemoteVersion: state.syncMeta.lastRemoteVersion,
    ...event
  });
  localStorage.setItem("vocab_machine_sync_audit_v1", JSON.stringify({ events: events.slice(-200) }));
}
```

## 11. 测试计划

### 11.1 配置错误测试

1. 未配置：灰色。

5. Push 失败：红色常驻。

5. 上传成功后 Gist revision 增加。
6. 清缓存前必须能通过备份导出看到当天数据。

### 11.4 回归事故测试

2. 正确填 Gist ID。
3. 学习若干词。
4. 观察状态灯。

预期：

- 系统必须立即报错；
- 不得显示绿色；
- 本地 pendingOps 存在；
- local snapshot 存在；
- daily backup 存在；
- Gist 不更新时 UI 必须明确说明云端未保存。
