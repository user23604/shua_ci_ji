**【项目背景】**
我需要开发一款名为“考研词汇自动刷词机 (Vocabulary Flashcard MVP)”的纯前端单页面应用（SPA）。它的核心理念是“降低认知负担的被动预热”，主打全自动定时播放、卡片滑动手势交互。本项目专为安卓设备（手机及平板）的【横屏模式 (Landscape)】使用而设计，供我个人专属使用。

**【技术栈要求】**

2. **横屏优先（核心）：** UI 必须 100% 适配手机和平板的横屏 (Landscape) 状态，全屏沉浸式体验。请使用 CSS 媒体查询 `@media (orientation: portrait)` 编写一个拦截提示层：如果检测到用户是竖屏打开，全屏黑底白字提示用户“请旋转设备至横屏使用”。

### 一、 数据源与自动化解析需求
应用不需要读取 JSON，而是直接通过 `fetch` 请求同目录下的本地 CSV 文件，文件名为：
`闪过考研词汇_高频词汇提取.xlsx - 词汇表.csv`

你必须在应用初始化时，编写一个健壮的 CSV 解析器（注意处理高频词汇中包含双引号、换行符的单元格文本）。CSV 的标准列名对应关系如下，请将其解析并映射为前端对象数组：
- `序号` -> 映射为 `id` (整数)
- `Unit` -> 映射为 `unit` (整数)
- `单词` -> 映射为 `en` (字符串)
- `真题词频` -> 映射为 `freq` (整数，若为空则为 0)
- `完整释义（保留红色）` -> 映射为 `zh_full` (字符串，需将内部的换行符替换为空格以便在卡片展示)
- `标红释义` -> 映射为 `zh_high` (字符串，部分单词可能为空)

### 二、 核心页面与功能模块需求

#### 面板 0：鉴权拦截页 (Auth 视图)
这是进入应用的绝对前置拦截页，必须在加载任何词库数据前执行。
1. **验证逻辑：** 应用初始化时，检查 LocalStorage 是否存有合法登录标志（`is_authenticated: true`）。如果有，进入 面板 1；如果没有，全屏只展示鉴权面板。
2. **UI 设计：** 极简风格。页面正中央提供一个密码输入框（type为 password）和一个“进入应用”按钮（支持回车键触发）。
3. **比对机制：** 在前端 JS 中硬编码访问密钥（默认写死为 `ky2027`）。输入正确则写入 LocalStorage 并进入面板 1；错误则输入框标红抖动提示。

#### 面板 1：设置与启动页 (Setup 视图)
进入应用的首屏，提供以下配置项（配置需自动保存在 LocalStorage，下次打开默认加载）：
1. **范围选择：** 下拉框或数字滑块选择目标 Unit（Unit 1 到 Unit 30）。
2. **模式选择：** 单选按钮：① 从选定 Unit 开头重新开始；② 恢复上一次学习进度（自动读取上次最后学到的单词 ID）。
3. **节奏控制参数：**
   - 单词停留总时长（滑动条：2秒-10秒可调）。
   - 中文释义延迟展示时间（滑动条：0秒-5秒可调，0代表中英文同时出现）。
   - 总结节点：可配置按“每 X 个单词”或“当前整个 Unit 结束”进行阶段总结。
4. **声音与语速控制：**
   - 英文/中文朗读开关 (Toggle)
   - 朗读语速调节 (滑动条：0.8x 到 2.0x，在 Web Speech API 中生效)。
5. **显示控制：**
   - 仅显示高频标红释义 (Toggle 开关，若开启，则卡片只渲染 `zh_high` 字段，若该字段为空则正常显示 `zh_full`)。
6. **云同步配置（关键）：**
   - 提供两个密码类型的输入框：`GitHub PAT (Token)` 和 `Gist ID`。
   - 提供两个按钮：【从云端覆盖本地】和【将本地推到云端】。
   - 填写的值需安全保存在 LocalStorage，仅供本地 JS 发起 Fetch 请求时调用，绝不可明文暴露。
7. **启动按钮：** 巨大的“开始刷词”按钮。点击此按钮时，必须触发一次静音的 `window.speechSynthesis.speak()` 以激活并解锁浏览器的自动播放音频限制。

#### 面板 2：核心播放页 (Flashcard 视图) - 横屏三栏布局
采用典型的 **左-中-右 三栏式横屏自适应布局**：
1. **左侧栏（导航控制区）：** 包含一个常驻的“返回设置页”按钮，以及当前进度状态（如：Unit 5 [12/85]）。
2. **中间栏（核心卡片显示区）：** 占据屏幕绝大部分核心视觉区域，居中摆放单词卡片。
   - 单词 (`en`) 字体要极大、极显眼，下方显示对应的中文释义。
3. **右侧栏（手势状态提示区）：** 在屏幕右侧边缘，用极简的半透明图标和文字固定显示手势说明，辅助单手大拇指握持时操作（上滑：斩 / 下滑：生词 / 左右滑：前后切换）。

**自动播放与手势逻辑：**
1. **自动播放流程：** 显示英文 -> （若开启语音）读英文 -> 等待“中文延迟时间” -> 显示中文 -> （若开启语音）读中文 -> 走完“单词停留总时长” -> 自动切下一个。任何手动滑动干预，必须立刻 `clearTimeout` 重置当前所有定时器。
2. **手势交互（在中间卡片区域触发）：**
   - **左滑：** 立即跳到下一个单词。
   - **右滑（撤销/回退）：** 返回上一个单词。*特殊逻辑：* 若上一个词已被打标（斩或重难点），回退后卡片上需额外浮现一个【撤销标记】按钮，点击清除其生熟状态。
   - **上滑：** 标记为“熟词/已斩”(Known)。卡片向上飞出，后台记录，自动跳下一个。
   - **向下滑动：** 标记为“重难点/生词”(Unknown)。卡片向下飞出，后台记录，自动跳下一个。

#### 面板 3：间歇总结页 (Break 视图)
达到设定的总结节点时，暂停自动播放并弹窗：
1. 显示本组数据统计：一共无感扫过多少词，斩了多少，标记重难点多少。
2. 提供一个显眼的【继续下一组】按钮。

#### 面板 4：归档复盘抽屉 (Archive 视图)
从主界面可随时点击进入：
1. 界面分为两个 Tab 面板：【已删词库(上滑的)】 和 【重难点词库(下滑的)】。
2. 内部展示结构：以 Unit 1、Unit 2... 为层级的折叠面板（Accordion），点击单元可展开查看该单元下所有被打标的单词列表。

### 三、 数据持久化与云同步接口规范 (Storage & Sync)
1. **一级存储 (LocalStorage)：** 实时记录设置参数、当前学到的 Word ID、以及打标数据结构（例如：`{ known: [1, 5], unknown: [2] }`）。
2. **二级存储 (GitHub Gist API)：** - 必须使用用户在【设置页】填写的 `PAT` 作为 `Authorization: Bearer <TOKEN>` 请求头。
   - 推送（PATCH）/拉取（GET）目标的 URL 为：`https://api.github.com/gists/<GIST_ID>`。
   - 同步的数据载荷为名为 `sync.json` 的文件内容，将 LocalStorage 中的进度数据序列化后进行推拉操作，实现跨设备多端进度同步。

### 四、 【技术架构与性能标准（必读核心）】
为了保证在安卓设备及平板上达到原生 App 级别的丝滑体验（60 FPS）及极高的稳定性，必须遵守以下规范：
1. **极简技术栈：** 推荐使用 Vue 3 (Composition API, CDN 引入) + Tailwind CSS。禁止引入任何庞杂的第三方移动端 UI 组件库（如 Vant 等），所有组件必须手写。
2. **GPU 硬件加速（生死线）：** 卡片的滑动位移、回弹动画，**绝对禁止**操作 `margin`, `top`, `left` 等属性。必须全程使用 CSS `transform: translate3d(x, y, 0)` 和 `rotate` 进行位移，并开启 `will-change: transform`，确保低端设备完全不掉帧。
3. **DOM 节点复用：** 页面 DOM 树中最多只允许存在当前卡片和下一张卡片（双层 DOM 结构），滑出的卡片必须立即销毁，严禁几千个单词堆积在 DOM 树中导致内存泄漏和浏览器崩溃。
4. **PWA 支持：** 编写 `manifest.json`（必须配置 `display: standalone` 且强制 `orientation: landscape`）并注册简单的 Service Worker 缓存资源，使其可完美“添加到主屏幕”作为独立全屏 App 离线运行。
5. **暗黑模式：** 必须使用 `@media (prefers-color-scheme: dark)` 完美适配系统深色模式，实现护眼黑底白字。
6. **防待机黑屏：** 使用 `WakeLock API` (若浏览器支持)，在进入 Flashcard 视图播放时，保持屏幕常亮，防止挂机时手机休眠。
