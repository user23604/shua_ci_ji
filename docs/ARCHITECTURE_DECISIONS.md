# 最终架构决策与修改边界

## 保持不变

- 一个用户可在手机、平板和电脑上共用同一个 Gist/`sync.json`。
- 设置属于本机偏好，不用云端强制覆盖另一设备当前 Unit、语速等界面状态。
- 所有学习动作先落本地；网络只负责异步交换。
- 不增加服务器、账号系统、数据库、设备分片文件或复杂构建框架。

## 核心安全决策

### 远端变化必须合并

只要本地存在业务数据且远端哈希相对基线发生变化，不论本地 dirty 标志是否为 false，都不得直接 Pull 覆盖。本地 clean 只说明“本设备自上次确认后没有新操作”，不能证明本设备保存的旧记录已完整存在于当前远端。

### 本地应用必须事务化

云端数据应用涉及多条 localStorage 记录。任何中途失败都必须恢复操作前的全部受影响键和关键内存状态；只保留覆盖前备份不足以防止当前会话继续使用半旧半新的状态。

### 网络失败只能降级云同步

中国大陆、VPN、代理、浏览器扩展或运营商链路都可能影响 GitHub API。程序保证本地学习、保存、导出和恢复继续工作，并限制重试；不承诺纯前端能让被完全阻断的 API 强行可达。

## 模块拆分标准

本轮将真正可独立测试的职责拆出：

- `08a/08b/08c`：哈希核心、状态迁移、错误状态；
- `27c`：同步编排辅助；
- `28a`：同步分支；
- `27-sync-tick.js` 与 `28-sync-push-patch.js` 保留主流程，但受审核心模块均不超过 500 行。

后续继续拆分必须同时满足：逻辑有独立输入输出、共享状态减少、有回归测试、数据格式和用户行为不变。生成的 `app.bundle.js` 不适用源码行数限制。

## 权威事实源

- 单词标记：`markStates`；`marks` 是兼容派生数据。
- 同步成功：远端验证后的 `baseRemoteHash`、`lastSuccessfulPushAt` 和当前会话确认。
- 本地待上传：业务 hash、持久游标/活动草稿和 dirty 状态的联合结果。
- 生产加载顺序：`app.js` 的模块清单。
- 生产运行文件：生成的 `assets/js/app.bundle.js`。

## 已知架构边界

- PAT 仍存储于浏览器 localStorage；共享设备、恶意扩展或同源脚本失陷时无法达到服务端密钥隔离强度。
- 客户端硬编码访问码只用于界面门槛，不是安全认证。
- 当日活动秒数、次数和 Unit 完成数采用幂等 `max` 合并；两设备真正并行产生的独立增量可能低估。精确累计需要引入事件 ID 或按设备 CRDT 计数器，不能直接改成求和。

## 禁止重新引入

- clean 本地直接覆盖式 Pull；
- 自动路径 `bypassBackoff: true`；
- hidden/pagehide 发起远端事务；
- 多套独立同步调度器；
- 未确认远端成功就显示绿色；
- 明文 PAT 进入日志、URL、诊断包或仓库；
- 没有迁移、回滚和测试就改变 `sync.json` 语义。
