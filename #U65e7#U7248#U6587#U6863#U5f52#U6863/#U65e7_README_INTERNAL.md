# 考研词汇自动刷词机内部 README

> 本文件给内部维护者和后续接手开发的人看。`README_INTERNAL.md` 已被 `.gitignore` 忽略，默认不随 Git 提交和推送。

## 1. 项目定位

这是一个纯前端、零构建工具的考研词汇刷词 SPA。目标设备是手机和平板，横屏和竖屏都能使用，可以直接部署到 GitHub Pages。

核心目标：

- 用 `27ky_shanguo_gaopin.csv`、`hongbaoshu_bikao.csv`、`hongbaoshu_jichu.csv` 作为词库，做自动刷词。
- 支持自动播放、手势标记、语音朗读、释义高亮、学习统计、复盘和 PWA 离线缓存。
- 保持文件结构简单，方便直接上传 GitHub Pages，不依赖 Node 构建流程。

## 4. 词库数据约定

当前内置词书配置在 `app.js` 顶部的 `BOOKS`：

```js
const BOOKS = [
  {
    id: "27ky-shanguo-gaopin",
    name: "27考研英语闪过高频词",
    csv: "27ky_shanguo_gaopin.csv",
    totalUnits: 30
  },
  {
    id: "hongbaoshu-bikao",
    name: "红宝书 必考词",
    csv: "hongbaoshu_bikao.csv",
    totalUnits: 26
  },
  {
    id: "hongbaoshu-jichu",
    name: "红宝书 基础词",
    csv: "hongbaoshu_jichu.csv",
    totalUnits: 30
  }
];
```

解析后统一映射为：

```js
{
  id,        // 数字 ID，按 CSV 行顺序/字段生成
  unit,      // Unit 编号
  en,        // 英文单词
  freq,      // 词频
  zh_full,   // 完整释义
  zh_high    // 高频/重点释义
}
```

CSV 解析器是状态机实现，支持：

- 普通逗号分隔
- 双引号包裹字段
- 字段内逗号
- 字段内换行
- 双引号转义

不要用简单的 `split(",")` 替换它。

红宝书两份源数据位于 `项目原数据词表以及交代md/`，线上使用的是根目录 CSV：

- `红宝书_必考词_提取.xlsx` -> `hongbaoshu_bikao.csv`
- `红宝书_基础词_提取.xlsx` -> `hongbaoshu_jichu.csv`

红宝书源数据没有“真题词频”列，转换后的 `真题词频` 当前统一为 `0`。这样会让词频水印显示为 `0 次`，但不会影响刷词、标记、统计、复盘、释义高亮和语音。

## 5. 页面与核心流程

### 5.1 鉴权页

- 默认密码：`ky2027`
- 登录状态写入：`localStorage.is_authenticated`
- 未登录时不加载词库，避免无意义请求和提前暴露数据。

### 5.2 设置页

主要设置项：

- 词书选择：当前有三本，支持闪过高频词、红宝书必考词和红宝书基础词。
- Unit 选择：根据 `totalUnits` 动态生成，并在每个 Unit 后显示当前进度和完整看完次数。
- 学习入口：重新开始或恢复上次进度。
- 播放倍速：滑杆调节，`0.5x` 到 `10.0x`，统一控制英文朗读、中文简读、中文出现延迟和自动跳词节奏。
- 中文出现延迟：保留独立设置，用来控制中文释义最早出现的时间。
- 阶段总结：每 X 个单词、当前 Unit 结束、手动点击完成。
- 语音：英文、中文开关；英文优先选择浏览器中更标准的英文语音包。
- 释义模式：完整释义或高频释义优先。
- 设置记忆：`settings.bookSettings` 会按词书分别记住 Unit、学习入口、播放倍速、中文出现延迟、总结方式、语音和释义模式。
- Gist 同步：只填写 GitHub PAT 和 Gist ID，应用自动拉取、自动推送。

### 5.3 刷词页

刷词页是核心体验：

- 横屏：三栏布局，左侧控制、中间卡片、右侧统计/动作。
- 竖屏：上下布局，卡片优先展示。
- DOM 只保留当前卡片和下一张卡片，滑动动画只用 `transform: translate3d(...) rotate(...)`。
- 英文单词强制单行，长词会根据容器宽度自动缩放。
- 中文释义按词性分行，`zh_high` 命中的内容用红色加粗高亮。
- 词频用绿色底色和水印表现，使用对数映射，避免齐夫分布下大部分词都接近白色。

手势规则：

- 左滑：进入下一个词。
- 右滑：回到上一个词。
- 首词右滑：只阻尼回弹，不循环到末尾。
- 上滑：标记为已斩。
- 下滑：标记为重难点/生词。
- 轻拨速度也能触发动作，不需要大幅度滑动。
- 滑动时卡片对应边缘会显示低强度光影，提示当前会触发的方向。
- 卡片上下左右边缘有透明点击热区：左侧点击是上一个，右侧点击是下一个，上侧点击是已斩，下侧点击是重难点；中间内容区点击暂停，暂停后再次点击当前卡片恢复播放，撤销按钮不触发暂停。
- 方向不要改反：左滑是下一个，右滑是上一个；点击左侧是上一个，点击右侧是下一个；点左侧旧卡向右飞出，点右侧旧卡向左飞出。

实时反馈：

- 顶部/侧边显示本轮 `扫过 / 已斩 / 重难点`。
- 计数随手势实时更新。
- 阶段总结页显示本轮数据。

### 5.4 阶段总结页

触发条件：

- 每 X 个单词。
- 当前 Unit 结束。
- 用户点击完成按钮。

总结页能力：

- 展示本轮扫过、已斩、重难点数量。
- 本轮有下滑标记时，显示“仅复习本轮重难点”。
- 点击后进入临时复习队列。
- 临时复习结束后回到原学习位置，不污染长期学习队列。

### 5.5 统计与复盘

统计抽屉包含：

- 今日、本周、本月学习时长。
- 扫过词数。
- 已斩/生词数。
- 周热力条。
- 月热力图。

复盘入口：

- 复盘今天：刷当天接触过的词。
- 复盘本周：刷本周接触过的词。
- 复盘本月：刷本月接触过的词。

复盘基于 `activity.days[date].wordIds`，不是基于已斩/生词列表。

### 5.6 归档抽屉

归档按当前词书隔离：

- 已删词库：`marks.known`
- 重难点词库：`marks.unknown`

同一个词在标记为已斩时会从重难点移除，标记为重难点时会从已斩移除。

## 6. 语音与时间控制

语音使用 Web Speech API：

- 英文朗读：`speakEn`
- 中文朗读：`speakZh`
- 播放倍速：`rate`

时间策略：

- 不再使用“单词停留总时长”参数。
- 中文出现延迟保留为独立参数；实际显示时间会随 `rate` 做倍速缩放，设为 `0` 时立即显示中文，不再等待英文朗读结束。
- 自动播放由英文朗读、中文出现延迟、中文简读预算、短间隔和 `rate` 共同决定。
- `rate` 同时影响英文朗读、中文朗读、中文出现延迟、静音阅读预算和自动跳词速度。
- 英文朗读优先选择 Google/Microsoft/系统中更标准的英文语音；找不到时回退到浏览器默认语音。
- 中文朗读不再读完整释义，优先读 `zh_high`；没有 `zh_high` 时按词性义项提取每个义项的一个概括词义。
- 卡片显示仍使用完整释义或高频释义优先模式，不受中文简读影响。

朗读高亮：

- 英文朗读时英文区域轻量高亮。
- 中文朗读时对应中文区域高亮。
- 浏览器支持边界事件时优先跟随事件；不支持时用估算节奏兜底。

注意：

- 不同浏览器、系统语音包和安卓 WebView 对 Web Speech API 支持差异很大。
- 中文逐字级别边界事件并不稳定，所以当前实现是“可用优先”的兼容方案。

## 7. 暂停、后台与 Wake Lock

后台挂起规则：

- 监听页面 `visibilitychange`、`pagehide`、`blur`。
- 一旦页面隐藏、失焦或切后台：
  - 记录当前卡片已经学习的时长。
  - 清除计时器。
  - 取消当前语音。
  - 释放 Wake Lock。
  - 标记为挂起状态。

回到前台：

- 不自动继续播放。
- 页面保留当前卡片清晰可见。
- 页面保留当前卡片清晰可见。
- 用户再次点击当前卡片后重新申请 Wake Lock 并继续当前卡片。

V1.2 已删除暂停态的全屏暗色遮罩和背景模糊，暂停就是为了能定格阅读。

## 8. PWA 与缓存策略

`manifest.json`：

- `display: standalone`
- `orientation: any`
- 允许横屏和竖屏使用。

`sw.js` 当前策略：

- 缓存版本：`vocab-machine-v18`
- `install`：`self.skipWaiting()`
- `activate`：`clients.claim()`，并删除所有旧版本缓存。
- 只删除 `vocab-machine-` 前缀下的旧缓存，避免误删同域其他应用缓存。
- 核心文件 Network-First：
  - `index.html`
  - `app.js`
  - `style.css`
  - `manifest.json`
  - `sw.js`
- 静态资产 Stale-While-Revalidate：
  - `27ky_shanguo_gaopin.csv`
  - `hongbaoshu_bikao.csv`
  - `hongbaoshu_jichu.csv`
  - `icon.svg`

`app.js` 的 SW 注册逻辑：

- 监听 `updatefound`。
- 新 SW 安装完成后发送 `SKIP_WAITING`。
- 监听 `controllerchange`。
- 新 SW 接管后静默刷新一次页面，避免继续运行旧 JS。
- 使用一次性标记防止反复刷新。

如果 GitHub Pages 上看不到新版本，优先检查：

- `sw.js` 的 `CACHE_NAME` 是否升级。
- 浏览器 DevTools 里 Service Worker 是否已激活新版本。
- Network 是否仍命中旧缓存。
- Pages 是否完成部署。

```text
localStorage.is_authenticated
```

```text
vocab_machine_settings_v1
```

保存全局设置，例如：

- `bookId`
- `unit`
- `rate`
- `summaryMode`
- `summaryCount`
- `speakEn`
- `speakZh`
- `highOnly`
- `zhDelay`
- `bookSettings`：按词书保存的设置快照，用来记住每本词书上次的 Unit、播放倍速、中文出现延迟、语音和显示参数。

### 9.3 云同步配置

```text
vocab_machine_cloud_v1
```

保存：

- GitHub PAT
- Gist ID

这是纯前端本地明文保存，只适合个人设备使用，不适合多人共享或公开设备。

### 9.4 同步元信息

```text
vocab_machine_sync_meta_v1
```

保存：

- `localUpdatedAt`：本地最近一次设置、进度、标记或学习活动变化时间。

自动同步用它和云端 `sync.json.updatedAt` 做兜底比较。当前冲突判断优先比较学习进度深度；只有进度相同才回退比较 `updatedAt`。

### 9.5 学习进度

```text
progress:<bookId>
```

保存当前词书的最后学习位置。

### 9.6 标记

```text
marks:<bookId>
```

结构：

```js
{
  known: [],
  unknown: []
}
```

### 9.7 学习活动

```text
activity:<bookId>
```

结构：

```js
{
  days: {
    "2026-06-10": {
      seconds: 0,
      words: 0,
      known: 0,
      unknown: 0,
      wordIds: []
    }
  }
}
```

热力图、日/周/月复盘都来自这里。

## 10. Gist 同步

同步文件名：

```text
sync.json
```

同步内容：

- `version`
- `settings`
- `progress`
- `marks`
- `activity`

自动同步方式：

- 用户填写 GitHub PAT。
- 用户填写 Gist ID。
- 页面初始化时，如果本地已有 PAT 和 Gist ID，会静默 GET 云端 `sync.json`。
- 云端为空、缺 `sync.json`、内容为 `{}` 或缺 `settings/progress` 时，不合并、不白屏，直接静默 PATCH 当前本地完整结构初始化云端。
- 如果 `sync.json` 是损坏 JSON 或 version 不兼容，只显示低调失败状态，不自动覆盖云端。
- 云端和本地都有数据时，先按整体学习进度深度比较；进度更多的一方胜出。
- 如果双方进度相同，再按整体 `updatedAt` 比较；本地胜出时会静默推送本地。
- 页面切后台、`pagehide`、刷词返回设置页、进入阶段总结页时都会静默推送。
- 隐藏态推送使用 `fetch` 的 `keepalive: true`。

UI 反馈：

- 不再有手动“从云端覆盖本地 / 将本地推到云端”按钮。
- 不使用弹窗，也不占用设置页 `setupStatus`。
- 界面边缘的小圆点会在同步中浅绿色呼吸闪烁，成功后常亮约 2 秒再淡出。

限制：

- PAT 明文存在本机 LocalStorage。
- GitHub API 受网络和权限影响。
- 这个方案适合个人多设备同步，不适合团队账号体系。
- 当前冲突策略是整体 payload 级别的“进度优先，时间兜底”，不做字段级合并。

- 本地学习进度深于云端时不会被旧云端覆盖，会静默推送本地。
- 双方学习进度相同时，才比较 `updatedAt/localUpdatedAt`。
- 切后台、`pagehide`、返回设置页、进入阶段总结页都会触发静默推送。
- 同步过程中只有小圆点反馈，不弹窗、不刷设置页同步文案。
- 冲突时进度更多的一方优先；进度相同时再比较 `updatedAt/localUpdatedAt`。

## 12. 新增词书步骤

1. 把新 CSV 放到项目根目录。
2. 在 `BOOKS` 中增加一项：

```js
{
  id: "new-book-id",
  name: "显示名称",
  csv: "new_book.csv",
  totalUnits: 30
}
```

3. 确认 CSV 字段能被 `mapWords()` 映射。
4. 如果新增源文件是 xlsx，先转换成根目录 CSV；根目录部署文件尽量使用 ASCII 文件名，避免 GitHub Pages、Service Worker 和部分系统编码问题。
5. 如果字段名不同，优先扩展字段别名或转换脚本，不要破坏现有词书。
6. 在 `sw.js` 的静态资源列表中加入新 CSV。
7. 升级 `CACHE_NAME`。
8. 本地 HTTP 测试后再推送 Pages。

## 13. 后续拓展建议

优先级较高：

- 给 `activity.days[date]` 增加 session 明细，支持早晚分段复盘。
- 给复盘模式增加“只复盘重难点”和“只复盘已斩”过滤。
- 给 Gist 同步增加字段级合并或冲突审计，避免多设备同时学习时整体覆盖粒度过粗。
- 给词库解析增加导入预检页面，显示字段映射、词数、Unit 分布。

优先级中等：

- 增加主题皮肤，但不要影响词频底色可读性。
- 增加更细粒度的手势灵敏度设置。
- 支持从 URL 参数直接进入某本词书/某个 Unit。
- 增加“今天目标时长”和“连续学习天数”。

谨慎处理：

- 不建议为了复杂 UI 引入构建工具，除非后续规模明显扩大。
- 不建议继续扩大 LocalStorage 里的明文敏感信息。
- 不建议把 CSV 解析改成脆弱的字符串拆分。
- 不建议把 PWA 缓存重新改回 Cache-First 核心文件策略。
